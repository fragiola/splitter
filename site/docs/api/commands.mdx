The model runs 15 commands. Each one takes a JSON payload, checked against its JSON Schema, and returns a `CommandResult`: `{ ok: true, value }`, or `{ ok: false, error }`. Run one with `model.run(name, payload)` (typed by your registry), or give it as untrusted JSON to `model.dispatch({ command, payload })`, which validates it first. `model.get("commands")` returns this same list with the schemas, ready to become tool definitions for an assistant.

Every command can return `invalid_payload` (the payload does not match its schema, with the path of each problem), `vetoed` (a middleware refused it), `queued` (a middleware ran it while another command was running) and `middleware_error`; each command lists the ones its own rules add: `not_found` (a group, panel or separator it names is missing) and `refused` (a rule of the splitter refuses the change).

Sizes in payloads follow React Resizable Panels: a number is pixels, a string carries its unit (`%`, `px`, `em`, `rem`, `vh`, `vw`), and a string without one is a percentage. A layout is always in percent. The payload types below use `T`, your registry of group and panel ids.

## Groups

### `group.add`

## Panels

### `panel.add`

Registers a panel in a group, with its constraints as declared (sizes: a number is px; a string carries its unit, %, px, em, rem, vh or vw; a string without one is %). Panels sort by order (their document position), so a panel rendered conditionally lands in its place. The group's layout becomes the saved one once the group holds exactly its saved panels, else the layout the group last had with its panels (the one it leaves is remembered for the panel set it had), else its default layout.

**Payload** (`PanelAddPayload<T>`)

| field | type | required | description |
| --- | --- | --- | --- |
| `id` | `string` | no | the new panel's id (generated when absent) |
| `groupId` | `string` | yes | the group the panel belongs to |
| `order` | `number` | no | where the panel sits among its group's panels (its document position); default: after the others |
| `minSize` | `number \| string` | no | the smallest size the panel takes when expanded (default 0) |
| `maxSize` | `number \| string` | no | the largest size the panel takes (default 100%) |
| `defaultSize` | `number \| string` | no | the size the panel starts with when no saved layout has one (default: an equal share of what is left) |
| `collapsible` | `boolean` | no | whether the panel can collapse below its minimum, to its collapsed size |
| `collapsedSize` | `number \| string` | no | the panel's size when collapsed (default 0) |
| `collapsedThreshold` | `number \| string` | no | how far past its minimum a drag goes before the panel collapses (default: halfway between collapsed and minimum) |
| `disabled` | `boolean` | no | the panel is resized neither directly nor by resizing its neighbours (code still can) |
| `groupResizeBehavior` | `"preserve-relative-size" \| "preserve-pixel-size"` | no | when the group resizes, keep the panel's percentage (preserve-relative-size, default) or its pixels (preserve-pixel-size) |

**Result** (`{ panelId: string }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `panelId` | `string` | yes | the new panel's id |

**Errors**: `not_found`, `refused`, besides those every command can return.

```ts
model.run("panel.add", {
    id: "nav",
    groupId: "main",
    order: 0,

});
```

## Separators

### `separator.move`

Moves a separator by delta percent of its group: positive grows the panels before it (the start side), negative the panels after it. The panels on the shrinking side give space nearest first, within their constraints; a collapsible panel snaps collapsed or open at its threshold; disabled panels do not change. A drag sends every step from the layout it started from (origin), as a transient step, then once more to commit. Refused when the separator or its group is disabled. Returns the layout applied.

It may run as a step of a continuous gesture: `model.run(…, { transient: true })`.

**Payload** (`SeparatorMovePayload`)

| field | type | required | description |
| --- | --- | --- | --- |
| `separatorId` | `string` | yes | the separator to move: `<beforePanelId>:<afterPanelId>` |
| `delta` | `number` | yes | how far to move it, in percent of the group: positive grows the panels before it |
| `origin` | `object` | no | the layout the move is measured from (a drag's layout when it started); default: the layout now |
| `source` | `"pointer" \| "keyboard"` | no | what moves it (default pointer): the keyboard collapses or expands a collapsible panel in one step instead of at its threshold |

**Result** (`{ layout: Layout }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `layout` | `object` | yes | the group's layout after the move |

**Errors**: `not_found`, `refused`, besides those every command can return.

```ts
model.run("separator.move", {
    separatorId: "nav:editor",
    delta: 5
});
```


## Batches

### `batch`

Runs several commands in order as one atomic step: if any fails, none applies. Emits one change event. Nested batches are flattened. An adapter registers a group and its panels with one batch.

It may run as a step of a continuous gesture: `model.run(…, { transient: true })`.

**Payload** (`{ commands: BatchEntry<T>[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `commands` | `object[]` | yes | the commands to run, in order |

**Result** (`{ results: unknown[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `results` | `JSON[]` | yes | each command's value, in order |

**Errors**: those of the commands it runs (the first failure, at its path in `commands`); nothing applies unless all succeed.

```ts
model.run("batch", {
    commands: [
        {
            command: "group.add",
            payload: {
                id: "main"
            }
        },
        {
            command: "panel.add",
            payload: {
                id: "nav",
                groupId: "main"
            }
        },
        {
            command: "panel.add",
            payload: {
                id: "editor",
                groupId: "main"
            }
        }
    ]
});
```
